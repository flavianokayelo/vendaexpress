# VENDA EXPRESS — Plano de Execução Local + Estrutura da Base de Dados

================================================================
COMO EXECUTAR LOCALMENTE
================================================================

1. Pré-requisitos
   - Node.js 18+ instalado
   - Navegador moderno (Chrome, Firefox, Edge)

2. Instalar dependências
   npm install

3. Iniciar o servidor de desenvolvimento
   npm run dev
   (O servidor arranca automaticamente neste ambiente — não executar manualmente)

4. Construir para produção
   npm run build

5. Fluxo de teste completo (simulação real)
   a) Abre a landing page em http://localhost:5173/
   b) Clica em "Criar minha loja" (ou vai para #/signup)
   c) Escolhe um plano (Starter, Business ou Premium)
   d) Preenche: nome da loja, email, palavra-passe
   e) O sistema cria automaticamente:
      - A conta do utilizador
      - A loja com subdomínio próprio (ex: joaoshop.vendaexpress.ao)
   f) É redirecionado para o painel (#/app)
   g) No painel, vai a "Produtos" > "Adicionar produto"
      - Preenche nome, preço, stock, imagem (URL)
      - Guarda
   h) No painel "Resumo", clica em "Ver loja" ou "Copiar link"
   i) Abre a URL da loja (#/s/joaoshop) numa nova janela
   j) Vê a loja pública com os produtos, adiciona ao carrinho, faz checkout

6. Conta demo já criada (para teste imediato)
   Email: demo@vendaexpress.ao
   Senha: demo123
   Loja: João Shop — acessível em #/s/joaoshop

7. Como funciona a persistência
   - Tudo é guardado no localStorage do navegador (JSON)
   - Os dados sobrevivem a recargas da página
   - Para limpar: DevTools > Application > Local Storage > remover "ve_mock_db_v1"

================================================================
ROTAS DA APLICAÇÃO (hash router)
================================================================

#/                    — Landing page (marketing + planos)
#/signup              — Registo de novo lojista (cria conta + loja)
#/signup?plan=ID      — Registo com plano pré-selecionado
#/login               — Login do lojista
#/app                 — Painel do lojista (dashboard)
#/app > produtos      — Gestão de produtos
#/app > categorias    — Gestão de categorias
#/app > pedidos       — Gestão de pedidos
#/app > clientes      — Lista de clientes
#/app > cupons        — Cupons de desconto
#/app > aparência      — Personalização visual (cor, logo, banner)
#/app > configurações — Dados da loja, moeda, WhatsApp, domínio
#/s/:slug             — Loja pública (qualquer pessoa pode ver e comprar)
#/admin               — Painel do administrador da plataforma

================================================================
ISOLAMENTO MULTI-TENANT (COMO FUNCIONA)
================================================================

Cada lojista só vê os dados da sua própria loja. O isolamento é feito
em JavaScript (não em RLS como no Supabase):

1. Ao fazer login, o user.id é guardado na sessão
2. Ao carregar dados, filtra-se por store_id onde stores.owner_id = user.id
3. Ao inserir dados, o store_id é sempre o da loja do utilizador logado
4. A loja pública (#/s/:slug) não precisa de login — qualquer pessoa pode ver
   e fazer pedidos (checkout de convidado)

================================================================
FLUXO COMPLETO: DO REGISTO À PRIMEIRA VENDA
================================================================

1. Visitante chega à landing page (#/)
2. Escolhe um plano e clica "Criar minha loja"
3. Preenche o formulário:
   - Nome da loja → gera automaticamente o slug (subdomínio)
   - Email + palavra-passe
4. Sistema cria:
   - Utilizador em users[]
   - Loja em stores[] com slug único
   - Sessão ativa
5. Redirecionado para o painel (#/app)
6. No painel:
   - Vai a "Produtos" > adiciona produtos (nome, preço, stock, imagem)
   - Vai a "Categorias" > cria categorias
   - Vai a "Aparência" > escolhe cor, descrição, logo, banner
   - Vai a "Configurações" > define WhatsApp, moeda
7. Clica em "Ver loja" no resumo → abre #/s/o-seu-slug
8. A loja pública mostra:
   - Banner + nome + descrição da loja
   - Filtros por categoria
   - Grelha de produtos ativos
   - Botão "Adicionar" em cada produto
9. Cliente adiciona produtos ao carrinho
10. Cliente aplica cupom (se tiver)
11. Cliente faz checkout:
    - Preenche nome, telefone, endereço
    - Sistema cria customer + order + order_items
    - Mostra confirmação
12. Lojista vê o pedido em "Pedidos" no painel
13. Lojista muda o estado do pedido (pendente → pago → enviado → entregue)

NOTAS
================================================================

- Esta é uma simulação completa com persistência local (localStorage)
- Não precisa de backend nem Supabase para funcionar
- Para produção real, substituir src/lib/supabase.ts pelo cliente
  Supabase real e aplicar a migration SQL (já existe em
  supabase/migrations/20260720080943_create_multi_tenant_schema.sql)
- A migration SQL cria as mesmas tabelas com RLS (Row Level Security)
  para isolamento real entre lojistas
- O esquema JSON e o esquema SQL são equivalentes em estrutura
